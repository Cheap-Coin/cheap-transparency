# Reward rules

Each active rules document must have a recorded SHA-256 digest in `HASHES.md`.
A rule change creates a new version; it does not rewrite the rules used for an
already committed drop.

Holder rules use `RULES-v*.md`. Community campaign rules use
`COMMUNITY-RULES-v*.md` and must disclose dates, funding, accepted actions,
points, caps, exclusions, review, and appeal terms before collection opens. A
file labeled as a test vector is validator evidence only and never creates a
live campaign.

Pre-launch Genesis rules must say that points are contribution records and do
not promise a token amount. Post-launch Surprise rules publish minimums, caps,
winner count, budget, candidate-freeze block, and entropy source. COST Diamond
rules remain social-independent. Likes, reposts, follows, comments, views,
follower counts, and passive Space listening are not rewardable actions.
